# UGC App Video Generator 后端接入总表（对齐版）


| 维度                            | 当前处理方式（现状）                                                                                                                                  | 可引入 PhotoGrid 现有能力代替                                                                                    |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 登录态接入（统一用户身份、租户、权限）           | **无**统一登录态接入。`/ugc-video-generator` 与当前 `/api/`* 路由未做用户鉴权；部分上游字段通过环境变量写死/兜底（如 `user_id/tenant_id/app_id`）。                                  | 接入 PhotoGrid 统一登录与鉴权中台（SSO/JWT/Cookie Session）、租户解析、RBAC 权限校验；在网关/BFF 层统一注入 `user_id/tenant_id/app_id`。 |
| 统一 BFF/API（稳定前端接口，屏蔽多上游）      | **部分有**：当前已用 Next.js API Route 做轻代理（如 `/api/upload`、`/api/create-task`、`/api/query-task`、`/api/ugc/`*、`/api/video/ima-pro`），但接口分散、版本与治理能力弱。 | 迁移到 PhotoGrid 统一 API Gateway + UGC BFF（版本化、错误码规范、熔断重试、限流、审计），上游供应商封装为 Provider Adapter。                 |
| AI 计费（积分冻结/扣减/退款、账单流水）        | **无**。当前无积分冻结/扣减/退款逻辑，无账单流水落库，无 token 成本归集。                                                                                                 | 复用 PhotoGrid 积分钱包/计费服务：预扣冻结 -> 成功结算 -> 失败/部分成功退款；同步账单流水（关联 `run_id/task_id/request_id`）。                |
| 任务中心（图片 run、视频 task 持久化与状态机制） | **部分有**：状态机主要在前端内存 + IndexedDB（`imageRuns/videoTasks` 本地保存），后端无统一任务中心与跨设备同步。                                                                | 接入 PhotoGrid 任务中心（后端任务表 + 状态机 + 查询 API）：`image_run/candidate/video_task` 持久化，支持跨端查询、重试、审计。              |
| 存储（图片/视频 URL 持久化、过期策略、可回放）    | **部分有**：上传和生成结果依赖上游返回 URL；本地仅存 URL 引用；缺少统一存储生命周期、过期策略和可回放治理。                                                                                | 接入 PhotoGrid 媒体资产服务（对象存储 + 元数据 + 生命周期策略 + 签名 URL 刷新）；支持素材可回放与归档。                                        |
| 回调与轮询（结果回传、失败重试、幂等保障）         | **部分有**：前端主导轮询；创建任务会传 `callback_url` 给上游，但当前项目无完整回调消费闭环；幂等保障不足。                                                                             | 接入 PhotoGrid 回调编排能力（回调接收、验签、重试队列、死信处理、幂等键）；前端改查后端任务状态，后端负责回调与补偿轮询。                                      |


## 备注

- 以上“现状”基于当前 Demo 代码实现对齐（前端页面 + `/api/`* 路由 + 本地 IndexedDB）。
- 建议先完成：`登录态 + 任务中心 + 计费` 三件套，再做存储治理与回调编排收口。
